## 5. 推荐发布路径

恢复 Git 发布时，执行以下单一路径：

1. 在当前项目包之外新建独立暂存目录，克隆远端 `main`，保留现有 4 个提交；
2. 从 `main` 创建建议分支 `consolidated/technical-baseline-20260810`，不得在旧 `main` 上直接覆盖；
3. 只按 `当前技术版本清单.json` 的权威源组导入代码、本体、4 个 Notebook、复现脚本和治理文档；
4. 排除 `00_官方材料`、`01_参赛交付物` 顶层冻结成品、所有 `历史版本`、`.venv-cuas`、`.runlogs`、缓存、身份材料和未授权大文件；
5. 在整合分支的实际目录结构中重新执行一键技术验收；若路径变化导致验收失败，先修复可复现入口，不降低验收标准；
6. 生成新的技术快照编号与 SHA-256，核对远端 README 的全部数字和链接；
7. 以 Pull Request 合并到 `main`，保留差异审查记录；禁止 `--force` 或 `--force-with-lease`；
8. 合并后再建立与快照编号一致的只读发布标签。

发布分支首先是“可复现技术仓库”，不是“完整报名材料仓库”。第 7、8 步恢复前，不上传冻结的方案书、PPT、视频和 ZIP。
