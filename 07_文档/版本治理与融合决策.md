# 版本治理与融合决策

更新日期：2026-08-10

## 1. 唯一主线

本项目从现在起只以 `智信2026_新概念反无_完整项目包` 为参赛主线和最终交付根目录。

- 项目叙事、本体模型、规则推理、贝叶斯飞轮、实验设计、论文和参赛材料：以完整项目包为准。
- 二维战术地图、二维/三维蜂群轨迹和展示节奏：从 `C-UAS-Final-Package` 中择优移植到完整项目包。
- `C-UAS-Final-Package` 只作为展示修复的参考源，不作为第二套参赛项目继续维护。
- GitHub 仓库 `wxyrc5/cuas-ontology-demo` 只作为早期 Streamlit 核心代码的远程快照，不反向覆盖本地主线。

## 2. 已核验的版本事实

### 本地两套项目

- 主线 `airports.json` 已加入 PKX/BRU/MUC 各三层长短轴、方向偏置和垂直高度参数，因此不再与 Final 包字节相同；这是有意的主线升级。
- `03_源码/streamlit_app` 是唯一运行入口；`streamlit_cloud_deploy` 是由同步脚本生成的部署镜像，当前技术验收已核对 30/30 个受管文件一致，仍不得手工修改或反向覆盖主线。
- 原机场页面在每一帧重新注入随机抖动，导致无人机跳动和乱飞；当前主线已改为固定种子、逐机固定弯曲度/方向/速度差和三波次高度。
- `C-UAS-Final-Package/scripts/viz12_v10_final.py` 使用固定种子、逐机固定弯曲度/方向/速度差和三波次高度，轨迹连续；拦截帧映射到 OODA 的“行动”阶段。这些机制是展示融合的主要依据。
- `C-UAS-Final-Package/scripts/gen_3d_html.py` 能生成交互三维页面，但页面中存在多组互相冲突的 OODA 数字，因此只能复用三维呈现方式，不能直接采用其中指标文案。

截至 2026-08-10，本轮通过 GitHub 应用逐页核实，远程仓库公开、默认分支为 `main`，且仅检出这一条分支。远程 `main` 仍仅有 4 个提交：

远端 README 仍含旧 AUC、无条件 OODA、`PEK` 误标、虚构团队、示例邮箱和占位网址；当前连接权限为 `pull=true`、`push=false`。完整审计及推荐发布路径见 `GitHub远端历史审计与发布策略.md`。

## 3. 融合规则

| 内容 | 权威来源 | 处理方式 |
|---|---|---|
| 总体项目逻辑与参赛叙事 | 完整项目包 | 保留并统一术语 |
| OWL/TTL 本体、SWRL、SPARQL | 完整项目包 | TBox/ABox 分离；HermiT/SHACL 正负向核验；SPARQL 直接查询正式图 |
| 二维蜂群轨迹 | Final 的 V10 轨迹机制 | 移植连续确定性曲线，删除逐帧随机抖动 |
| 二维地图底图 | Final 的真实地图思路 | 生成并随包携带离线底图，避免演示时因网络导致空白 |
| 二维/三维防御区域 | Final 的三波次高度与交互视图 + 主线机场参数 | 移植连续轨迹；将等距边界升级为各机场三层非圆二维/三维防御包络 |
| 指标数字 | `05_Notebook与数据/验证输出/指标裁决.json` | 只能引用本次执行值，并保留“固定种子合成仿真/非现场实测”限定 |
| 报名表与提交命名 | 赛事官网及官方模板 | 原件只读，另存填写，最终签字盖章扫描 |

## 4. 当前已发现的冲突

| 冲突项 | 完整项目包 | Final 展示包 | 当前决定 |
|---|---:|---:|---|
| AUC | 旧稿 `0.9958 ± 0.0011` | 旧稿 `0.9764` | 均废止；本次同预算贝叶斯 AUC=`0.967892` |
| 固定基线 AUC | 旧稿 `0.5682 ± 0.0264` | 旧稿 `0.5832` | 均废止；本次同案例、同五通道、同观测预算固定规则 AUC=`0.868806`，ΔAUC=`0.099085` |
| OODA 闭环 | 多处宣称 `< 5 s` | V10 约 `8 s`，另有页面写 `3.8 s`、`5.20 s` | 均废止；20 机 HPM 完整闭环均值=`3.164 s`、P90=`3.670 s`、P(小于5s)=`0.9896`，含传感/通信/授权/瞄准/效应/BDA，但仍非现场实测 |
| 本体一致性 | 旧版只做 RDFLib 结构检查 | 无统一结果 | 当前 8 OT/10 LT TBox + 正向 ABox 通过 HermiT；互斥类型负向对照被拒绝；SHACL 正向与两项负向对照通过 |
| 20 机蜂群 P_k | 旧稿预写 `≥0.75` | 视觉脚本另有预设 | 当前容量约束动态反馈闭环 Pk=`0.7655`，Wilson 下界=`0.7596`；同资源静态覆盖表 Pk=`0.3007` |
| 蜂群规模外推 | 无一致口径 | 视觉脚本可任意增加目标 | 固定资源扫描前沿是 N=20；25 机 `0.2903`、30 机 `0.0337`、40/50 机 `0`，不得隐藏失败或外推无限规模优势 |
| 资源增配 | 无可查询容量口径 | 视觉脚本只增加目标或装备图标 | 使用 Notebook 02 的 20–100 机 × 1–6 同构资源包协调感知实验；点估计 Pk≥0.75 最少需 1/2/2/2/3/3/4/5 包，点估计 Pk≥0.95 最少需 2/2/2/3/3/4/5/6 包；必须披露共享融合航迹、批量授权、跨包协调时延、合成假设和非采购报价边界；100 机 6 包虽点估计 0.9523，但 Wilson 下界 0.9441，不能宣称 95% 置信下保证 Pk≥0.95 |
| 机场代码 | 大兴/ZBAD 被错误写作 `PEK` | 同样沿用错误 | 已按中国民航局公开代码统一为 `PKX/ZBAD`；`PEK` 仅出现在历史版本说明中 |

旧提案、PPT、网页和视频仍可能含有已废止数字；在完成逐项回填前均视为“待修订”，不得直接提交。

## 5. 目录治理

- `03_源码/streamlit_app`：本地演示主入口。
- `03_源码/streamlit_cloud_deploy`：由 `streamlit_app` 机械同步并在当前验收中 30/30 一致的云端部署镜像；不得手工修改，也不得作为上游事实源。
- `05_Notebook与数据`：实验唯一可复现入口，保存执行环境、输入、随机种子和新鲜输出。
- `06_部署脚本`：Windows 本地启动、Jupyter 启动和验收脚本。
- `00_官方材料`：官网原件及后续填写副本；官方原件不可覆盖。
- `.runlogs`：仅用于本地诊断和渲染检查，不进入最终 ZIP。

## 6. 完成判据

技术主线已满足前四项；用户已要求本轮暂不处理申报书/PPT/视频与正式提交包，因此第 5–7 项明确延期：

1. 本地主入口一条命令启动，所有页面无异常；
2. 二维底图在断网时仍可见，轨迹连续且同一输入可重复；
3. 三维轨迹与二维使用同一仿真数据和拦截事件；
4. 全部 Notebook 在隔离环境中从头执行成功；
5. 项目提案、PPT、视频和网页中的指标与新鲜实验输出逐项一致；
6. 官方报名表、身份证明、提案和视频按官网命名规则分别打包；
7. 最终提交目录不包含虚拟环境、缓存、日志、临时渲染和旧版本副本。
