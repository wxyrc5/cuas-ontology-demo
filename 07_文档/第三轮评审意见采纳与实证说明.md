# 第三轮评审意见采纳与实证说明

版本：2026-08-12  
适用范围：Markdown 方案、4 分 30 秒初筛视频脚本、Streamlit 现场演示和答辩口径。  
证据原则：能在当前软件夹具中复现的写“已实现”；需要外部数据、装备或专家的写“待验证”；无法核实或明显错误的建议不采用。

## 1. 采纳结论

| 建议 | 裁决 | 当前处理 | 证据边界 |
|---|---|---|---|
| 让本体价值肉眼可见 | 采纳 | 本体页增加热插拔对比：新增一套 Equipment/Context 语义声明后，使用原查询发现新装备；SHACL 同步校验 | 仅证明当前夹具的数据热插拔，不证明 SQL 天生不能热插拔 |
| “SQL 改 200 行、2 周；本体 1 条三元组、5 秒” | 拒绝原数字 | 左侧只列刚性集成需要核对的变更面，数字标为待项目实测；右侧展示当前实测的 16 条语义声明、0 个可执行代码文件改动、查询不变、无需重启 | 一个完整装备实例不可能只靠一条三元组满足当前 SHACL；无基线工程证据不能虚构人天/代码行 |
| OperatorWorkload 加入贝叶斯飞轮 | 部分采纳 | 增加透明认知负荷代理量和 L1/L2/L3 授权矩阵，但不作为第六个 Beta-Binomial 成功通道 | 工作负荷是决策上下文/协变量，不天然是一次伯努利成败观测；五通道 AUC 保持可比 |
| 低风险高置信度自动授权 | 安全化采纳 | L1 自动仅限可逆、非外部效应的扫描/融合/隔离/WTA 重算；L2 要求操作员明确批准；HPM/HEL/动能、低置信度或禁射界冲突进入 L3 指挥员明确批准 | 工作负荷升高不能降低授权等级；L3 不是“只给否决窗口”的默认放行 |
| 失败数字线程爆炸图 | 采纳 | 增加 Observation→Fusion→WTA→Equipment→Failed Effect→Threat 图，以及 SPARQL 逆向根因候选查询 | 当前是可追溯规则，不是已识别的统计因果效应 |
| 结构因果模型、do-算子和因果归因 | 降格为下一阶段 | 当前记录 intervention/action、前后状态和证据；保留反事实敏感性图；P1/P2 再定义 DAG、混杂变量、识别假设和验证集 | 在没有干预数据与可辩护识别假设时，不把 What-if 分数包装成 SCM 因果效应 |
| 所有融合统一 UTM-50N | 拒绝全局硬编码，采纳任务局部 CRS | PKX/BRU/MUC 分别使用 EPSG:32650/32631/32632；流事件显式携带源/目标 CRS、requiresTransformation 与状态；PROJ/pyproj 转换失败时隔离事件 | UTM 分区随经度变化；跨区或大范围场景应使用任务指定工程 CRS/地心坐标，不能全球固定 50N |
| WTA 数学显式化 | 采纳 | 增加 0-1 MILP：最大化 ΣPijxij，受效应器容量、单目标唯一分配和禁配矩阵约束；20 目标约束自动验收 | 这是算法夹具，不是实装 WTA 求解时延或物理 Pk |

## 2. 热插拔比较如何避免偷换概念

SQL 不是本体的反义词，PostgreSQL 也可以采用元数据驱动、EAV、JSONB、插件注册表或配置化规则。公平问题应当是：**在相同的新装备能力声明任务下，两条实现链需要修改哪些受控工件，旧查询和旧调度是否继续工作，服务是否需要重启，回归测试范围有多大？**

当前可重复的右侧证据是：

1. 向当前 RDF 图加入 16 条满足约束的 Equipment 与 SpatiotemporalContext 声明；
2. 不修改原有 HardKill 能力查询；
3. 查询结果新增 `Eq_DE_Hotplug_002`；
4. SHACL 正向通过；
5. 可执行代码文件改动为 0，当前进程无需重启。

左侧“刚性表结构 + 硬编码规则”只作为后续同题基线，必须用真实分支记录 schema migration、查询、调度白名单、测试和启动行为后才给出代码行/耗时。当前视频不得展示“200 行、2 周”之类未经测量的数字。

## 3. 人机共驾的安全边界

| 等级 | 当前允许范围 | 触发与人员 | 预算含义 |
|---|---|---|---|
| L1 | 扫描模式、融合模型、提高确认门、隔离故障装备并重算候选 WTA | 系统自动；动作必须可逆且不产生外部效应 | 软件动作预算；不是武器释放授权 |
| L2 | 已有预案内的低风险软处置/资源重分配与批次决策 | 操作员明确批准 | 通过批次压缩降低点击数，不取消责任边界 |
| L3 | HPM、HEL、动能、高风险效应、低置信度、禁射界或空间冲突 | 默认拒绝，指挥员明确批准 | 响应预算是参数化人因假设，待工作坊/台架标定 |

认知负荷代理量由目标数、待审批 Action、竞争链路和禁射界冲突线性组合并截断到 [0,1]。它用于 UI 告警、批次聚合和时延压力分析，**不能**用来把 L3 降成 L2/L1。

## 4. 因果表述边界

当前系统能够回答：

- 哪个观测被哪个融合节点使用；
- 哪条 WTA 决策选择了哪个装备；
- 哪个 Action 生成了什么 Effect；
- 失败节点向前追溯时，哪些健康/射界条件命中显式规则；
- 在共享观测下，把雷达健康度或备份路径作为情景变量改变时，后验敏感性如何变化。

当前系统**不能**在统计意义上证明“主动隔离 HPM 造成任务成功率提高多少”。要升级为 SCM，至少需要预先声明 DAG、处理选择偏差和共同原因、给出干预/准实验数据、验证一致性与 positivity，并区分总体效应、直接效应和个体反事实。本轮只实现“因果就绪的可追溯记录”，不声称因果识别完成。
