# 事实口径与答辩边界

更新日期：2026-08-12（以本轮四个 Notebook 和 8 个 Streamlit 入口验收结果为准）

## 一句话项目定义

本项目是面向机场等重点场所的反无人平台语义决策与数字化试验原型：以本体统一“使命—场景—能力—装备—威胁—资产—人员—效果”，以 SPARQL 支持可追溯查询，以五通道贝叶斯反馈、全链路 OODA 和资源约束蜂群裁决辅助识别、预警、处置方案比较和效果复盘。

- 当前正式模型保持 8 个核心 Object Type、10 个核心 Link Type，并增加 3 个扩展类型、6 个扩展关系；浏览夹具包含 26 个核心数组实例和 45 条核心关系；
- TBox 378 triples，正向 ABox 242 triples，合并图 620 triples；

## 不可以说

- “国内首创”“国际领先”“已达到实战/部署要求”，除非有独立查新、鉴定或试验；
- “机场实测”“专家标注”“真实识别率”“实装拦截率”；
- 把 HermiT/SHACL 的当前版本结论扩大为“所有未来实例和 SWRL 规则均已证明正确”；
- 把参数化 OODA 时延表述为现场链路实测；
- 把合成使命 Pk 当作物理武器杀伤概率；
- 宣称固定资源能够对任意规模蜂群维持高成功率；
- 把“复制同构资源包”的规划实验说成已经部署多阵地，或把资源包数、合成行动成本说成采购报价；
- 宣称多资源包协调时延已由真实竞争链路、跨阵地台架、逐目标授权或现场电磁环境标定；
- 继续使用旧 AUC 0.9958/0.9922、旧固定规则 0.5682、旧 20 机 Pk 0.181、约 0.39 s 软件处理链或旧动画 8 s；
- 把二维/三维防御包络说成监管净空范围；
- 把本地 Action 原型说成商业平台部署、SWRL 在线执行、实时装备控制或已经批准的作战指令；
- 把北京大兴写成 PEK。正确代码是 PKX/ZBAD。

## 必须主动披露的缺口

1. OODA 分量、资源容量和单次作用 Pk 是可查询的工程假设，尚未由第三方或机场现场标定；
2. 当前固定资源在 25 机及以上不达标，失败结果必须保留；
3. 资源增配只复制独立并行动作容量，不提高单次作用 Pk，也不缩短基础 OODA；协调感知主口径加入随资源包数和目标规模增长的跨包同步、去冲突与指令编组时延，理想并行结果只作为上界；
4. 新增协调时延仍是参数化假设，尚未覆盖真实竞争链路吞吐、丢包、跨阵地时钟同步和物理射界冲突；逐目标人工授权、传感退化和 HPM 离线等压力工况仍会显著降低闭环使命成功率；
5. SWRL 已作为设计态规则规范修正，运行态是独立的闭世界 SPARQL/确定性 Action 引擎；商业平台部署、SWRL 在线执行、真实专家标注一致性、真实传感器数据和机场现场试验不在本轮证据范围内；
6. 二维/三维轨迹、处置动作和设施位置均为参数化演示。

## 推荐答辩表述

“我们没有把软件仿真包装成装备实测。当前成果证明的是：8/10 核心加 3/6 扩展的形式模型可满足且实例约束可检出错误；设计态语义验证与运行态快速 Action 已分离；五通道反馈在同预算下优于固定规则；固定资源在 20 机达到内部 0.75 门槛、25 机开始明显失效。本体健康条件先验还能表达主雷达失效和备份能力重构。进一步扩群只用于给出资源规划边界，并不宣称无限蜂群或现场多阵地能力。”
