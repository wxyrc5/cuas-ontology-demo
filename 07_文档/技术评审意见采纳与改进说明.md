# 技术评审意见采纳与改进说明

版本：v1.0（2026-08-12）  
适用对象：昆仑智镜（KunLun MirAI）“智盾·反无任务编排与验证台”

## 1. 总体裁决

本轮不重写《反无人机体系本体模型技术方案文字稿》的四层主线，仍以 Mission—Scenario—TechnicalCapability/Equipment—Effect/EffectMetric 闭环讲故事。原有“8 个核心 Object Type、10 个核心 Link Type”保留为稳定口径；评审指出的物理效果、信号、时空上下文以 **3 个扩展类型、6 个扩展关系**加入，避免前后版本再次失去共同基线。

## 2. 逐项采纳矩阵

| 评审意见 | 裁决 | 已实现证据 | 对外口径 |
|---|---|---|---|
| Action Type 与 Function 形式化断层 | 采纳 | `action_contract.schema.json`、`action_contract.py`；8 条 Action 均含 preconditions、side_effects、validation_function、expected_revision、evidence_refs | 当前是本地确定性运行态原型，不是实装控制接口 |
| SWRL/HermiT 与 OODA <5s 冲突 | 采纳 | `cuas-rules.swrl` 明确为设计态规范；`runtime-trigger-queries.sparql` 与 Python Action engine 用于运行态；HermiT/SHACL 不在实时链路 | <5s 是参数化完整闭环仿真，不是 DL 在线推理时延 |
| Effect 与 EffectMetric 混淆 | 采纳 | `cuas:Effect`、`causesEffect`、`affectsThreat`、`quantifiedBy` 与实例 `Effect_HPM_Disruption_001` | Effect 是实际行为/物理效果，EffectMetric 是量化结果 |
| 缺少 Signal/Communication | 采纳 | `cuas:Signal`、`emitsSignal`、`observesSignal` 与 `Signal_RF_RemoteControl_20` | 当前只实现语义对象和公开参数夹具，不声称接入真实链路 |
| 时空/坐标系建模不足 | 采纳 | `SpatiotemporalContext` 包含 CRS、WKT、精度、UTC 时间戳、ENU 速度；SHACL 验证 | 为兼容 OWL 2/HermiT，推理层 WKT 使用 xsd:string；GeoSPARQL datatype 在运行态适配 |
| BFO/CCO 顶层本体挂接 | 部分采纳，暂不写入强公理 | 采用 SOSA/SSN、GeoSPARQL 语义参考；建立版本锁定与映射评审任务 | 不采用未经核对的 `cco:StasisOfMaterialEntity`；未锁定版本前不宣称正式 BFO/CCO 对齐 |
| Shared Property / Value Type | 采纳其工程意图 | Shared Property 统一为 OWL Datatype/ObjectProperty；状态、动作、事件契约由 SHACL/JSON Schema 约束值域 | OWL 没有 Palantir 意义上的原生 Value Type；用标准约束等价表达 |
| 完整 SWRL + SPARQL 触发规则 | 采纳 | 修正 R1、R2、R4 的 domain/range 断裂和未定义 `sameCapability`；增加四条运行态闭世界查询 | SWRL 文件是设计态可交换规范；比赛原型没有冒充 Protégé 在线执行 |
| SAPIENT 高频数据到 RDF 管线 | 部分采纳 | `streaming_semantic_contract.json` 定义 JSON/Protobuf 解码、校验、单位/坐标归一、对象物化、触发、授权、回写链 | 是 SAPIENT-like 平台中立适配契约，不是 ASM 实机接入 |
| 贝叶斯应与本体联动 | 采纳为补充实验 | `evaluate_ontology_conditioned_counterfactual` 与 `fig3_7_ontology_counterfactual.png` | 主实验仍是五通道 Beta-Binomial；补充实验只做先验敏感性，不称为真实 Pk |
| 固定规则模型对照 | 已实现并保留 | Notebook 03 的同案例、同通道、同预算 ROC/AUC | 对比证明合成基准上的区分能力，不代表现场识别率 |
| 20 机裁决失效与继续扩群 | 已修复，适度扩展 | 20 机闭环验收；20–100 机资源包扩展只用于说明容量前沿 | 20 机是主展示；25–100 机放附加证据，不抢核心故事 |
| 数字线程贯穿 | 采纳 | 原始事件→语义对象/关系→规则命中→Action→人工门→Effect/Metric→Notebook/哈希证据 | 当前是可追溯软件数字线程，不是全生命周期实装数字工程平台 |
| “130pm SRR-2024”与“国标 2026-03-01” | 暂缓 | 未获得可公开核验的准确题名、编号和原文 | 未核实前不作为规范依据或参考文献 |

## 3. BFO/CCO 对齐策略

比赛阶段不远程 `owl:imports` 未锁定版本的 BFO/CCO，也不凭印象写入 `rdfs:subClassOf`。下一阶段应依次完成：锁定发布版本和许可证；建立 Mission、Equipment、Effect、Signal、Context 的映射表；用 competency questions 验证映射不会产生不可满足类；再将对齐模块作为独立 TTL 导入。这个裁决比“先挂上根类再说”更符合一致性、离线复现与自主可控要求。

## 4. 公开标准与实现依据

- W3C SOSA/SSN 2023：Sensor、Observation、Actuator 与 Actuation 的标准语义框架：<https://www.w3.org/TR/vocab-ssn-2023/>。
- OGC GeoSPARQL 1.1：空间对象、几何和空间查询规范：<https://docs.ogc.org/is/22-047r1/22-047r1.html>。
- W3C SWRL Submission：OWL 规则表达的公开语法依据：<https://www.w3.org/submissions/SWRL/>。
- Drools Rule Engine、Apache Flink CEP：后续运行态规则编译与流处理的候选适配器；当前包未部署：<https://docs.drools.org/latest/drools-docs/drools/rule-engine/index.html>、<https://nightlies.apache.org/flink/flink-docs-stable/docs/libs/cep/>。

## 5. 评审时一句话说明

“我们把 OWL/HermiT/SWRL 放在设计态做语义正确性，把已物化的 SPARQL 触发和经过 JSON Schema 校验的 Action 放在运行态做快速闭环；本体不仅是字典，还通过 Equipment—Capability—EffectMetric 拓扑与健康度改变贝叶斯先验，并在主雷达失效时给出可解释的备份能力重构。”
